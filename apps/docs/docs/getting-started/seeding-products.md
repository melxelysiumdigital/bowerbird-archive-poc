# Seeding products

The `apps/export/` folder contains a Shopify product export CSV used to seed a fresh dev store. This page covers what's in it and how to import it.

## What's in `apps/export/products_export.csv`

A standard [Shopify product CSV](https://help.shopify.com/en/manual/products/import-export/using-csv) with two kinds of rows:

### POC-relevant: archive digitisation services

These are the products the web app uses to model digitisation requests. Pricing and variants reflect the archive's quote structure.

| Handle | Title |
| --- | --- |
| `audio-digitization-service` | Audio Digitization Service |
| `document-copy-service` | Document Copy Service |
| `film-digitization-service` | Film Digitization Service |
| `map-copy-service` | Map Copy Service |
| `microfilm-copy-service` | Microfilm Copy Service |
| `photograph-copy-service` | Photograph Copy Service |

### Shopify sample data (leftover from the dev store starter)

These come from Shopify's default dev store seed and have nothing to do with the archive — they're snowboards. Leaving them imported is harmless for testing but you'll want to filter them out of any production-shaped dataset.

`the-3p-fulfilled-snowboard`, `the-archived-snowboard`, `the-collection-snowboard-{hydrogen,liquid,oxygen}`, `the-compare-at-price-snowboard`, `the-complete-snowboard`, `the-draft-snowboard`, `the-hidden-snowboard`, `the-inventory-not-tracked-snowboard`, `the-minimal-snowboard`, `the-multi-location-snowboard`, `the-multi-managed-snowboard`, `the-out-of-stock-snowboard`, `the-videographer-snowboard`, plus `gift-card` and `selling-plans-ski-wax`.

## How to import the CSV

Follow Shopify's [Import products with a CSV file](https://help.shopify.com/en/manual/products/import-export/using-csv) flow:

1. In the Shopify admin: **Products → Import**
2. Pick `apps/export/products_export.csv`
3. Tick **Overwrite any current products that have the same handle** if you're re-seeding a store you've imported into before. Leave it unticked on a fresh store.
4. Click **Upload and preview**, review the summary, then **Import products**.

The import runs as a background job. You'll get an email when it finishes. Even small CSVs typically take a few minutes.

### CLI alternative

You can drive imports from the CLI via the [Admin GraphQL bulk operations API](https://shopify.dev/docs/api/usage/bulk-operations/imports). For the POC the admin import flow is faster — bulk operations are worth it if you find yourself re-seeding daily.

## How the file was produced

Generated by Shopify's built-in export ([Exporting products](https://help.shopify.com/en/manual/products/import-export/export-products)):

1. **Products → Export**
2. **All products** (or filtered)
3. **CSV for Excel, Numbers, or other spreadsheet programs**
4. Download the email link Shopify sends, save the file to `apps/export/`

To refresh the snapshot, replace `products_export.csv` in place — the filename is what `apps/web` and any scripts assume.

## Things that won't transfer cleanly

Read this before you import to a production-shaped store.

### Image URLs point at the source store's CDN

The `Image Src` column contains absolute URLs like `https://cdn.shopify.com/s/files/1/.../image.jpg`. On import, Shopify **re-downloads** each image and re-uploads it to the destination store's CDN. Two failure modes:

- If the source store gets de-provisioned or the image is removed, the URL 404s and the product imports without an image.
- Large image sets slow the import dramatically (Shopify fetches each image serially).

**Mitigation**: keep the source store alive until the import finishes, or pre-host images somewhere stable and rewrite the column.

### Metafields require definitions to exist first

The CSV contains two metafield columns inherited from the original dev store:

- `Snowboard binding mount (product.metafields.test_data.binding_mount)`
- `Snowboard length (product.metafields.test_data.snowboard_length)`

Shopify's import **will not auto-create the metafield definition** — the namespace and key must exist on the destination store before import, or the values get dropped silently. Create them under **Settings → Custom data → Products** before importing if you care about preserving them. For the POC the `test_data` metafields are sample-data noise — safe to ignore.

When you add real archive metafields (e.g. `archive.shelfmark`), define them on the destination store first, then export → import.

### Variants and inventory

Multi-row products: each variant lives on its own row, sharing the `Handle`. The first row has the product-level columns (Title, Body, Vendor, etc.); subsequent rows have only the variant-specific columns populated. This is normal and expected by Shopify's importer — don't try to "flatten" rows.

Inventory quantities **are not** included in the standard product CSV. Set them after import via **Products → Inventory** or via the [InventoryLevel API](https://shopify.dev/docs/api/admin-graphql/latest/objects/InventoryLevel).

### Market-specific pricing

The export includes Canadian market columns:

- `Included / Canada`
- `Price / Canada`
- `Compare At Price / Canada`

These only work if the destination store has [Shopify Markets](https://shopify.dev/docs/apps/build/markets) configured with a Canada market. Otherwise the columns are ignored.

### Status

Each product row has a `Status` column (`active`, `draft`, `archived`). Imported products keep their source status — review the **draft** ones in the admin before you assume your store is "ready".

## Re-exporting after edits

If you edit products in the dev store and want the changes back in the repo:

```bash
# In Shopify admin: Products → Export → CSV (for spreadsheet programs)
# Email yourself the file, save it as:
apps/export/products_export.csv

# Then commit
git add apps/export/products_export.csv
git commit -m "Refresh seed products from dev store"
```

Diffing CSVs in git is messy but tolerable for ~60 rows. If the file ever grows past a few hundred products, consider switching to a JSON shape via the bulk operations API.
